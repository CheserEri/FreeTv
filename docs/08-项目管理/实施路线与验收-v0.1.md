# YTV 实施路线与验收 v0.1

## Phase 1A：工程与视觉骨架（1 周）

建立 Flutter Windows 工程、主题令牌、路由、假数据 Repository 与首页/频道/收藏页面。  
**验收：** 不联网也能浏览 6 个演示频道；键盘焦点连续、无死角；设计规范中的色彩和间距不重复硬编码。

## Phase 1B：官方播放承载 POC（1 周）

实现 `OfficialWebPlaybackGateway` 与独立播放页，打开官方电视页面，加入加载、失败、返回和全屏壳层。  
**验收：** Windows 中能手动完成官方允许的播放；页面未加载时不白屏；关闭播放页会释放 WebView；不记录或暴露认证与播放数据。

## Phase 1C：本地体验闭环（1 周）

接入 SQLite，完成收藏、历史、设置及网络异常文案。  
**验收：** 重启可恢复收藏和历史；清除历史可验证；断网、官方页失败、需要登录均有对应状态。

## Phase 1D：平台决策（POC）

在 Android 与 Android TV 分别验证 WebView 播放、全屏、返回键、焦点和遥控器。  
**验收：** 分平台形成测试报告。任何一个平台失败不阻塞 Windows MVP，但不得宣称该平台支持。

### 2026-09-19 闸门解锁记录

两条阻塞项经真机域名观测后已决策，闸门放行：

1. **W-2 / W-3 判定口径** —— 降级为「导航级白名单 + 事后检测」。W-3 明确判为不适用，
   风险由数据边界（不导出 Cookie/Token/DOM/媒体地址）兜底，17 主机观测清单留档为残留风险证据。
2. **白名单粒度** —— 观测到官方电视页一次加载涉及 17 个主机，跨 `yangshipin.cn`（13 个子域）
   与 `ysp.cctv.cn`（直播流本体）。白名单改为**可注册域标签边界匹配**，登记两个域；
   刻意不放行 `cctv.cn` 全域、`o.alicdn.com`（第三方埋点）与 `mediadata.xuexi.cn:8443`（疑似链路注入）。

**残留风险（不阻塞，需持续跟踪）：**

- 子资源请求不经过白名单（W-3 不适用），官方页面或其引入的第三方脚本可自由发起网络请求；
- S-4 登录态不可检测，播放页不区分「未登录」与「已登录」。

### 2026-09-19 频道目录与单频道直达

**观测方法**：只读官方电视页**自身已经渲染出来**的内存数据（频道名、分类、`pid`），
不调用官方接口、不重放请求、不解析播放流，属于契约预期的「开发期人工观测官方公开页面」。

**结论**：

1. **单频道直达地址已确认**。官方电视页路由定义为 `{path:'/tv/home', query:{pid}}`；
   实测 `?pid=600001811` 直达 CCTV13、`?pid=600002475` 直达湖南卫视，打开即选中该频道。
   `pid` 是官方公开地址中的频道标识，不是接口凭据。实现见 `OfficialPages.tvChannel`。
2. **目录补全**：登记官方电视页「CCTV」页签 40 条 +「卫视」页签 33 条，共 73 条静态种子，
   每条都带各自的单频道直达地址。原「六个演示频道」全部共用电视页入口的做法已废弃。
3. 官方页面标注「(VIP)」的 10 个频道登记为 `restricted`（需要会员）；
   标注「(限免)」的 3 个按可观看登记。中国教育电视台 1 频道归入 `other`。

**效果**：在应用内点击频道即定位到官方页面的对应频道，不需要二次点击切换。
