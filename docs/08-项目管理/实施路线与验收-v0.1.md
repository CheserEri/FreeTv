# YTV 实施路线与验收 v0.1

## Phase 1A：工程与视觉骨架（1 周）

建立 Flutter Windows 工程、主题令牌、路由、假数据 Repository 与首页/频道/收藏页面。  
**验收：** 不联网也能浏览 6 个演示频道；键盘焦点连续、无死角；设计规范中的色彩和间距不重复硬编码。

## Phase 1B：官方播放承载 POC（1 周）

实现 `OfficialWebPlaybackGateway` 与独立播放页，打开官方电视页面，加入加载、失败、返回和全屏壳层。  
**验收：** Windows 中能手动完成官方允许的播放；页面未加载时不白屏；关闭播放页会释放 WebView；不记录或暴露认证与播放数据。

## Phase 1C：本地体验闭环（1 周）

接入 SQLite，完成收藏、历史、设置及网络异常文案。  
**验收：** 重启可恢复收藏和历史；清除历史可验证；断网、官方页失败、需要登录均有对应状态。

## Phase 1D：平台决策（POC）

在 Android 与 Android TV 分别验证 WebView 播放、全屏、返回键、焦点和遥控器。  
**验收：** 分平台形成测试报告。任何一个平台失败不阻塞 Windows MVP，但不得宣称该平台支持。

| 闸门 | 通过条件 | 未通过处置 |
|---|---|---|

## 闸门执行结果（2026-09-18）

依据《WebView POC 白名单与隐私测试清单 v0.1》第 5 节在 Windows 真机执行，逐项证据见该文档。

| 闸门 | 结论 | 依据 |
|---|---|---|
| 官方页面 | **通过（口径调整后）** | 官方电视页可在 WebView2 内加载并渲染 CCTV-1 直播画面；登录弹窗由官方页面自行弹出。W-2 按「事后检测 + 退回」口径实现，W-3 判为不适用（插件能力边界），详见《白名单与隐私测试清单》1.2 与 6.2。 |
| 登录 | 通过 | 用户在官方页面内自行完成认证；YTV 不读取、不替代。登录态无法被检测（检测需读 DOM，与隐私项 P-2 冲突），记为限制。 |
| WebView 兼容性 | 部分通过 | 加载、返回、释放、不白屏均通过；30 分钟长稳（S-1）、断网（S-3）、受限内容（S-5）尚未执行。 |
| 数据授权 | 维持 | 无授权来源，继续使用本地种子目录，不启用 BFF。 |

### 2026-09-19 闸门解锁记录

两条阻塞项经真机域名观测后已决策，闸门放行：

1. **W-2 / W-3 判定口径** —— 降级为「导航级白名单 + 事后检测」。W-3 明确判为不适用，
   风险由数据边界（不导出 Cookie/Token/DOM/媒体地址）兜底，17 主机观测清单留档为残留风险证据。
2. **白名单粒度** —— 观测到官方电视页一次加载涉及 17 个主机，跨 `yangshipin.cn`（13 个子域）
   与 `ysp.cctv.cn`（直播流本体）。白名单改为**可注册域标签边界匹配**，登记两个域；
   刻意不放行 `cctv.cn` 全域、`o.alicdn.com`（第三方埋点）与 `mediadata.xuexi.cn:8443`（疑似链路注入）。

**残留风险（不阻塞，需持续跟踪）：**

- 子资源请求不经过白名单（W-3 不适用），官方页面或其引入的第三方脚本可自由发起网络请求；
- S-4 登录态不可检测，播放页不区分「未登录」与「已登录」。

### 2026-09-19 频道目录与单频道直达

**观测方法**：只读官方电视页**自身已经渲染出来**的内存数据（频道名、分类、`pid`），
不调用官方接口、不重放请求、不解析播放流，属于契约预期的「开发期人工观测官方公开页面」。

**结论**：

1. **单频道直达地址已确认**。官方电视页路由定义为 `{path:'/tv/home', query:{pid}}`；
   实测 `?pid=600001811` 直达 CCTV13、`?pid=600002475` 直达湖南卫视，打开即选中该频道。
   `pid` 是官方公开地址中的频道标识，不是接口凭据。实现见 `OfficialPages.tvChannel`。
2. **目录补全**：登记官方电视页「CCTV」页签 40 条 +「卫视」页签 33 条，共 73 条静态种子，
   每条都带各自的单频道直达地址。原「六个演示频道」全部共用电视页入口的做法已废弃。
3. 官方页面标注「(VIP)」的 10 个频道登记为 `restricted`（需要会员）；
   标注「(限免)」的 3 个按可观看登记。中国教育电视台 1 频道归入 `other`。

**效果**：在应用内点击频道即定位到官方页面的对应频道，不需要二次点击切换。

**结论：保持开源，只提供源码，不提供安装包或任何二进制分发物。**

### 依据

《央视频软件许可及用户服务协议》第八条与第九条中，与本项目直接相关的条款：

| 条款 | 原文要点 |
|---|---|
| 8.2.4 | 不得对软件运行中释放到终端内存的数据、客户端与服务器端的交互数据…进行复制、修改、增加、删除、**挂接运行**或创作衍生作品，形式包括使用插件、外挂或**非央视频经授权的第三方工具/服务接入本软件和相关系统** |
| 8.2.5 | 不得将用于上述用途的软件、方法进行运营或向公众传播，**无论这些行为是否为商业目的** |
| 8.2.6 | 不得通过非央视频开发、授权的第三方软件、插件、外挂、系统登录或使用本软件及相关服务，或**制作、发布、传播上述工具** |
| 2.3.1 | 许可范围限于「为**非商业目的**在**单独一台**终端设备上安装、使用、显示、运行」 |
| 9.3 | 未经书面同意，不得为**任何商业或非商业目的**许可第三方实施、利用上述知识产权 |
| 9.6 | 不得私自使用「央视」「央视频」等商标、服务标记、品牌特征 |

要点：8.2.5 与 8.2.6 **不区分是否营利**，因此「免费、非营利」不构成抗辩；8.2.6 同时规制「制作、发布、传播工具」的行为本身。

### 架构侧的有利事实（经代码核实）

以下为降低**法定**侵权风险（著作权、反不正当竞争）的既有设计，须继续维持：

- 应用自身零网络请求，仅 `loadRequest` 到官方地址，无 HTTP 客户端；不复制、不存储、不转播内容；
- 无 JS 注入（`runJavaScript` / `addJavaScriptChannel` 均未使用），不修改官方页面；
- 只做导航级白名单，**不拦截子资源、不屏蔽广告**；
- 不绕过会员或 DRM：`restricted` 频道仅作标注，仍由官方页面自身把关；
- 不使用任何官方商标与 Logo（`Channel.logoAsset` 从未赋值）。

### 后续必须维持的红线

1. 不提供安装包、绿色包、预编译二进制，或任何形式的分发链接；
2. 不引入广告屏蔽、会员绕过、内容下载、媒体地址解析等能力；
3. 不叠加遮挡官方登录、授权、版权与广告提示的控件；
4. 不使用「央视」「央视频」等标识作为项目名称或图标。

> 本节为工程侧风险判断，不构成法律意见。若日后需要公开分发，应先取得官方书面授权。
